# Simple setup command

## Outcome, scope and classification

Replace the rejected inline-Python prototype with a genuinely short command. For an updated installed helper, setup displays `"$HOME/.local/bin/ytdlp-setup" 1.3.2`, not Python source. Keep bootstrap instructions honest when no launcher is installed. Preserve dependency confirmation and all existing diagnostics.

This is complex: it adds a helper CLI capability and installer-owned launcher, crosses the pong/UI contract, and needs old-helper/bootstrap compatibility and security validation. The parent is integration owner. Two distinct implementation workers and two independent read-only reviewers are mandatory. Prior uncommitted Python-fallback changes are the starting state, not user work to discard wholesale; preserve their safety properties as logic moves into the helper.

Local implementation/testing only. Do not commit, push, release, install real packages, replace the installed user helper, change live browser profiles, add permissions, publish a new package or execute a real remote installer. Preserve published v1.3.1 assets. Local extension version becomes 1.3.2; native/minimum helper becomes 1.3.0. The future v1.3.2 release URL is intentionally not published; local tests use harmless fixtures. Publication requires a later user request.

## Decisions and invariants

1. Put bounded download/run logic in the existing native helper, dispatched only by explicit CLI `--setup VERSION`. No native-message/RPC action executes setup. Ordinary Firefox startup arguments (manifest path and add-on ID per MDN) continue to use the framed server unchanged.
2. VERSION is exactly three numeric components, bounded length and no whitespace, options or URL characters. Default download is the fixed repository's HTTPS `/releases/download/vVERSION/setup.sh`; preserve default verified TLS, 30-second socket timeout, at most 1 MiB, nonempty response, complete fetch before Bash and proper child failure status. Errors are friendly and nonzero, not a Python traceback for normal expected failures. No shell-evaluated program strings.
3. Preserve the installer interaction: Bash inherits terminal/session/stdout/stderr, receives the script through stdin and still reads confirmation from /dev/tty. CLI may support only `--no-deps` and `--dry-run`; never silently add --yes. Dry-run performs no download, execution or filesystem mutation. Unknown flags fail before I/O. Ctrl-C is handled cleanly.
4. A test-only `YTDLP_SETUP_BASE_URL` override may point only at an explicit HTTP loopback fixture; it is not exposed through the extension. Normal production remains version-pinned HTTPS. Reject unsafe/non-loopback overrides rather than broadening remote execution targets.
5. `setup.sh` installs a managed executable at `$HOME/.local/bin/ytdlp-setup`. Wrapper begins exactly `#!/bin/sh` and `# Managed by yt-dlp Downloader`, then execs the actual supported Python in isolated `-I` mode, the installed host path, `--setup` and safely quoted `"$@"`. Generate safely for paths containing spaces/apostrophes. No PATH/profile modifications.
6. Refuse to overwrite an unmanaged file or symlink at that launcher path, ideally before other installation side effects. Updates may replace only owned launchers. Uninstall removes only a marked owned launcher, works without Python and preserves unrelated files. Dry-run reports launcher operations without creating files. Prefer atomic launcher replacement and no new release asset/checksum placeholders: the launcher is generated from the already verified host installation.
7. Add `pong.setupLauncher = {found: bool, path: string|null}`. Found means the canonical HOME launcher is an executable regular non-symlink file with the managed header, not just any similarly named program. No execution probe. CLI and wrapper downloads are not triggered by ping.
8. Add a setup-only `setupLauncher` checklist row, bringing the full checklist to 13. Missing is a warning, unknown is pending; neither alone blocks downloads. Required minimum-helper rules still apply. Choose launcher whenever the capability is verified, even when the helper needs a later protocol update; otherwise use known curl/wget, then a clear manual download/prefix fallback. Never show or copy raw Python bootstrap source.
9. Shared command generation returns the literal safe HOME-based command with validated VERSION, not a raw shell command from the host. Browser fallback returns `bash ` as a prefix, with explicit download-and-drag-full-file-path instructions and browser downloads-list alternative. Relabel the asset link `Download setup.sh`. Do not guess Downloads or silently execute a selected file. Clipboard content must match displayed command/prefix.
10. Remove the superseded inline-Python frontend branch and associated prototype fields only within this task's hunks. Preserve equivalent download/error/quoting tests in the helper/launcher suites. Existing published curl/wget, state derivation, trusted text rendering, visibility polling, copy fallback and busy-port reconnection protections remain intact.
