A short, managed setup command

Extension 1.3.2 and helper 1.3.0 replace the rejected inline-Python bootstrap with "$HOME/.local/bin/ytdlp-setup" 1.3.2, a launcher the installer creates and owns. When no launcher is installed, setup keeps honest curl, wget or download-and-drag instructions.

Plan: plans/archive/simple-setup-command.md · handoffs: native, frontend. The plan archive is git-ignored, so these links work only in the local checkout.

What changed

  • Helper CLI: ytdlp_host.py --setup VERSION [--no-deps] [--dry-run] downloads the pinned release setup.sh over verified HTTPS (30 s timeout, at most 1 MiB, nonempty, fully fetched) and only then pipes it to bash. No native-messaging request can start setup, and Firefox's normal startup arguments still reach the framed server.
  • Launcher: setup.sh writes a #!/bin/sh wrapper marked # Managed by yt-dlp Downloader. It refuses to overwrite unmanaged files or symlinks, replaces atomically, and uninstalls without Python. It never edits shell profiles.
  • Capability: pong.setupLauncher = {found, path} is reported only for an executable regular file with the managed header. The setup page gains a 13th, setup-only checklist row.
  • Command choice: verified launcher → curl or wget one-liner → bash prefix with download-and-drag instructions. The page never shows or copies Python source or a command string supplied by the host.

Follow-up fixes

Found by rerunning the full suites on bash 5.0.18 / Python 3.11
IssueDisposition
sh setup.sh runs bash in POSIX mode; bash < 5.1 rejects < <(…) process substitution (e.g. RHEL 8). Present since 47f2bd3, so published v1.3.1 is affected too. Fixed: set +o posix right after the bash guard.
test_wget_fallback raised TypeError when wget is not installed. Fixed: the real-download helper skips when the tool is missing.

Remaining limits

  • Real-browser desktop, mobile and copy check waived by the user. This Sailfish OS host has no sudo or package manager, Playwright Chromium and T3's preview browser cannot start (missing libatk, libX11, libgbm and others), and the system browser would touch a live profile. The fake-DOM page suite (165 tests) covers states, rendering and copy and was accepted as sufficient.
  • shellcheck is not installed here; the CI and release workflows run it.
  • No real package manager, remote installer, live browser profile or installed user helper was used.
  • Docs and CHANGELOG are prepared for 1.3.2 (dated 2026-10-26), but the release is not tagged or published yet. Until it is, the v1.3.2 URLs in the docs and the launcher's pinned download do not exist.
