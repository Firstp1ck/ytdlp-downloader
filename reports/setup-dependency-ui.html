Dependency setup, visible and actionable

Required failures prevent Ready. Optional or installer-only warnings remain visible without blocking downloads. The user runs the terminal setup command and confirms package installation.

This report records source validation and independent review. The GitHub release page records publication and downloadable assets. Mozilla submission is left to the user.

One diagnostic contract, shared UI state

  • Old helpers explicitly request version 1.2.0. Python cannot be checked independently if no helper can start.
  • Visible pages keep polling for actionable warnings or unknown checks; hidden pages pause. A fully healthy page stops scheduled polling.
  • Python repair requests a guarded idle reconnection. Installing XDG directory detection refreshes the default for future downloads, without redirecting jobs already created.
  • The installer parses distro identity as data, asks before package installation, honors no-op flags and never adds repositories or AUR tools. Proxy/RHEL package offers use existing repository metadata.

Install and publish separately

  1. Install ytdlp-downloader-1.3.1.xpi. This GitHub package is unsigned; Mozilla submission/signing is a separate user action.
  2. Update the helper from the setup page. Its command is pinned to the matching release:
curl -fsSL https://github.com/Firstp1ck/ytdlp-downloader/releases/download/v1.3.1/setup.sh | bash

If testing from the checkout instead, run the local script. This changes helper registration and asks before installing missing packages:

cd ytdlp-downloader
bash native-host/setup.sh --host-file native-host/ytdlp_host.py --dry-run
bash native-host/setup.sh --host-file native-host/ytdlp_host.py

For Mozilla, submit the versioned XPI through the website. Readable source is packaged directly; reproducible packaging uses Python's standard library:

python3 native-host/build_xpi.py extension dist/ytdlp-downloader-1.3.1.xpi

Evidence and remaining limits

  • Canonical local plan and dispositions. The local archive is intentionally ignored by Git.
  • Native diagnostics and download lifecycle; consent-based installer.
  • Shared setup state; setup rendering and polling; settings/popup regressions.
  • Protocol and architecture; release notes; Mozilla reviewer notes.

Confidence in source-level behavior is high, supported by tests, independent reviews and browser fixtures. Real package installation across every supported distro, actual interpreter replacement, sandbox-browser compatibility and an actual Python 3.8 runtime were not exercised. Presence checks do not prove every optional desktop tool will work in a particular graphical session.

No system packages or live browser profiles were changed during development. No Mozilla submission was performed. Baseline Bash, a working package manager and administrative authority cannot be created by an installer that lacks them; clear manual guidance remains necessary.
